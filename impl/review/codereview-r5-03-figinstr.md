## Findings

### Finding 1 — MEDIUM | `maglab/instrument/manual_rag.py:421–433, 440–445` | SQLite connection not closed when an exception occurs in `SCPIIndex.build()` and `SCPIIndex.load()`

**Defect.**
Both `SCPIIndex.build()` and `SCPIIndex.load()` open a `sqlite3` connection using the bare form `conn = sqlite3.connect(...)`, then call `conn.close()` only at the end of the happy path. If any operation between `connect()` and `close()` raises an exception, the connection is never closed.

In `build()` (lines 421–433):
```python
conn = sqlite3.connect(self._db_path)
conn.execute("CREATE TABLE IF NOT EXISTS chunks ...")
conn.execute("DELETE FROM chunks")
for i, (chunk, vec) in enumerate(...):
    conn.execute("INSERT INTO chunks ...", ...)  # ← exception here leaks conn
conn.commit()
conn.close()   # ← never reached on failure
```

In `load()` (lines 440–445):
```python
conn = sqlite3.connect(self._db_path)
rows = conn.execute("SELECT data, vec FROM chunks ORDER BY id").fetchall()  # ← exception here leaks conn
conn.close()   # ← never reached on failure
self._chunks = [SCPIChunk.from_dict(json.loads(r[0])) for r in rows]       # ← JSONDecodeError here also OK (conn already closed)
```

For `build()`, the risk is highest: the embedding call `self._embedder.embed(texts)` runs before `connect()`, so if that raises the conn is not yet open — safe. However, any `sqlite3.OperationalError` (e.g., disk full, DB locked) during `conn.execute("DELETE FROM chunks")` or the insert loop leaks the connection. CPython's reference-counting GC will eventually finalize the connection object, but this is non-deterministic and violates the resource-safety contract in a long-running session.

**Fix.** Use the context manager form, which calls `conn.close()` on exit (including exceptions):
```python
# build()
with sqlite3.connect(self._db_path) as conn:
    conn.execute("CREATE TABLE IF NOT EXISTS chunks ...")
    conn.execute("DELETE FROM chunks")
    for i, (chunk, vec) in enumerate(zip(chunks, self._vecs, strict=False)):
        conn.execute("INSERT INTO chunks (id, data, vec) VALUES (?, ?, ?)",
                     (i, json.dumps(chunk.to_dict()), json.dumps(vec)))
    conn.commit()

# load()
with sqlite3.connect(self._db_path) as conn:
    rows = conn.execute("SELECT data, vec FROM chunks ORDER BY id").fetchall()
```

Note: `sqlite3` context manager calls `commit()` on clean exit and `rollback()` on exception — `conn.commit()` can be dropped from `build()` in the rewrite.

### Finding 2 — LOW | `maglab/figure/renderers/schematic.py:358, 476` | Unsanitized `panel_id` embedded in SVG XML comment — `-->` in panel_id creates malformed XML

**Defect.**
`SchematicRenderer.render_panel()` embeds `panel.panel_id` directly into an SVG XML comment without sanitization:

```python
# schematic.py line 358
svg = assemble_svg(
    primitives_with_params,
    ...
    provenance=f"panel_id={panel.panel_id}",  # ← panel_id inserted verbatim
)
```

The same pattern appears in `_empty_svg()` at line 476.

The provenance string is inserted into the SVG comment slot in `_SVG_HEADER_TEMPLATE`:
```
<!-- Generated by MagLab schematic.py — panel_id=<provenance> -->
```

If `panel.panel_id` contains `-->` (which XML/SVG prohibits inside comments), the resulting file is malformed XML. Verified:
```
panel_id = "test --> <script>alert(1)</script> <!--"
→ SVG: <!-- Generated by MagLab schematic.py — panel_id=test --> <script>...</script> <!-- -->
```

When this SVG string is passed to `cairosvg.svg2png(bytestring=...)` in `compose.py` (line 167), `cairosvg` uses `lxml` for XML parsing, which raises `XMLSyntaxError` on encountering `-->` inside a comment. This causes a silent fallback to the grey placeholder in `compose.py` (lines 169–171), making the schematic panel invisible in the composed figure with no user-visible error (only a `log.warning`).

`panel_id` is validated by Pydantic as a plain `str` with no character restrictions, so any user- or LLM-authored `FigureSpec` can trigger this. The impact is incorrect figure output (missing schematic panel) with a misleading grey placeholder and no clear error message.

**Fix.** Strip `--` (and replace with `__`) from the provenance string before inserting it into the comment, since XML comments cannot contain `--`:
```python
safe_panel_id = panel.panel_id.replace("--", "__")
provenance=f"panel_id={safe_panel_id}",
```

Or apply the sanitization inside `assemble_svg()` before constructing the header:
```python
provenance_safe = provenance.replace("--", "__")
header = _SVG_HEADER_TEMPLATE.format(..., provenance=provenance_safe)
```

## Items Investigated and Found Sound

The following areas were probed adversarially and found to be correct:

- **Safety gate bypass** — `skip_safety_check=True` is not exposed in the public `generate_measurement_script()` convenience function and is explicitly hardcoded to `False` in the CLI entry point (`cli.py`). No bypass vector.
- **Shell injection via Inkscape** — `subprocess.run()` uses a list form (no `shell=True`). The Inkscape binary path comes from `shutil.which()`. No injection surface.
- **Path traversal in manual download** — `_try_download()` and `_cache_path()` both apply `re.sub(r"[^\w\-]", "_", ...)` to manufacturer and model names before joining to the cache root. `Path.name` on the input PDF eliminates directory components.
- **`_model_to_class_name` with empty/all-symbol models** — returns `""` which is caught by the `or "GenericInstrument"` fallback in `scaffold.py` line 131.
- **SCPI safety compound-command semicolons** — correctly handled by sub-command splitting. `*RST; SOUR:VOLT 1000` correctly flags VOLTAGE_OVER despite the `*RST` branch using `continue`.
- **`_OUTPUT_ON_RE` / `_OUTPUT_OFF_RE` regex coverage** — handles `:OUTP ON`, `OUTP ON`, `OUTPUT ON`, `:OUTP 1`, `OUTP OFF`, etc. Correctly does NOT match `:OUTP:STAT ON` (sub-node command).
- **`SweepConfig.step=0` validation** — correctly rejected by the `field_validator`.
- **`_extract_xy` with empty DataPoint list** — returns `([], [])` safely; callers are always guarded by `_require_datapoints` which raises `IntegrityError` before `_extract_xy` is reached.
- **`_cosine_similarity` with mismatched vector dimensions** — truncates to min dimension; returns `0.0` for zero-norm vectors. No divide-by-zero.
- **`FigureComposer._make_axes` bounds check** — correctly validates both start position (`>= nrows/ncols`) and span end (`> nrows/ncols`).
- **Figure resource leaks** — `compose.py` closes `fig` in `except` clause; `render_single()` closes on error. `SimVizRenderer.render_panel()` wraps the `fig_tmp` rasterization in `try/finally`.
- **`check_script_text` line-number approximation for duplicate commands** — documented as "approximate" in the docstring. The `setdefault` approach (first-occurrence wins) matches the documented limitation and is consistent.
