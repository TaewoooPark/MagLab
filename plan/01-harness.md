## 5. 에이전트 하네스 & 오케스트레이션

### 5.1 하네스 = LLM을 둘러싼 비계

LLM 추론을 제외한 모든 인프라 — 에이전틱 루프, 도구 실행, 컨텍스트 관리,
메모리, 제어 흐름, 안전·관측. 독립 CLI 프로그램이므로 MagLab가 이 하네스를
*자체 보유*한다 (Codex CLI·OpenCode 패턴: 프롬프트 조립 → 모델 호출 → 도구
실행 → 재귀; ~85% 컨텍스트 충전 시 compaction).

### 5.2 워크플로 vs 에이전트

복잡성은 입증으로 얻는다. 단계 고정 작업(`gen→validate→run→parse→fit`,
효과 피팅, 멀티스케일 핸드오프)은 워크플로로; 탐색적 작업만 개방형 에이전트로;
반복 구현·검토·작성은 Ralph 루프(§6)로.

### 5.3 연구 루프 = 백트래킹 트리

연구 루프는 선형 파이프라인이 아니라 가지치기·역추적 가능한 트리(AI Scientist
v2 EPM 교훈). 오케스트레이터(`core/orchestrator.py`)가 과학 전략(목표 분해·
트리 노드·위임·종합·종료 판단)을 소유한다. 위상은 orchestrator-workers 기본.

### 5.4 서브에이전트 & 컨텍스트 격리

서브에이전트는 자기 컨텍스트에서 대량 데이터를 소화하고 압축된 결론만
돌려준다. v1: `literature-scout`·`sim-designer`·`sim-runner`·`result-analyst`·
`effect-fitter`·`physics-validator`·`hypothesis-gen`·`figure-designer`·
`instrument-codegen`·`manual-ingest`·`reviewer-persona`(×N)·`section-drafter`·
`comms-writer`(×N). 서브에이전트 정의 포맷·6요소 계약·검증 설계는 §5.16.

### 5.5 컨텍스트 엔지니어링 & 메모리

- 컨텍스트는 유한·감쇠 자원. 시스템 프롬프트 altitude, 도구 큐레이션, JIT
  검색(레지스트리·색인만 사전 로드, 본문은 적시).
- compaction은 파라미터 이름·provenance ID·잡 ID를 보존. `MAGLAB.md`(불멸
  파일)는 프로젝트 컨텍스트.
- 메모리 3계층: 작업 컨텍스트 / 세션 상태(SQLite) / 장기 메모리
  (`memories/*.md`, grep 검색 — 검증된 설정·물질 보정·문헌 노트·불량 파라미터).

### 5.6 MagLab 스킬 시스템 (SKILL.md 오픈 표준)

MagLab는 독립 프로그램이지만 스킬 시스템을 자체 보유한다 — **SKILL.md 오픈
표준**(agentskills.io; Claude Code·Codex·Gemini CLI·Cursor 등 30+ 제품 호환).

- 스킬 = 디렉터리 + `SKILL.md`(YAML frontmatter: `name`·`description` + 본문).
  선택적 참조 파일·스크립트 번들.
- **3단계 점진 공개**: ① 시작 시 `name`+`description`만(~100토큰/스킬)
  ② 트리거 시 SKILL.md 본문(<5k토큰) ③ 참조 파일은 필요 시만.
- `core/skills.py` 로더가 `.maglab/skills/`, `~/.local/share/maglab/skills/`,
  번들 `skills/`에서 발견. MagLab가 *생성*하는 스킬(장비 스킬 §13.3)도 동일
  표준이라 Claude Code·Codex 등에서 재사용 가능. 카탈로그 = 부록 C.
  SKILL.md 전체 명세·저작 규칙·스킬 자동 생성 파이프라인은 §5.17.

### 5.7 검증 루프 — 결정론 우선

① 결정론 검증(sanity oracle·정적 검증기·Custodian·χ²/R²·µMAG 표준문제·
인용 DOI 검증·효과 피팅 잔차·물리 경계) ② Evaluator-Optimizer(생성기 ↔
*다른* 평가기, 최대 반복 상한) ③ LLM-as-judge는 비정량적인 것에 한해.
**정량·인용·피팅 검증에 LLM 판사 금지.** figure는 비전 모델 critic(§12.5)로
보조하되 데이터 일치는 결정론 검사.

### 5.8 자율성 · 가드레일 · 장기 실행

- 자율성 모드: copilot(기본) / semi-auto / autonomous. 액션 cost-tier(0 자동 ~
  3 사람만 — 장비 코드 실제 실행·리뷰 패치 적용·논문 투고는 Tier 3).
- 가드레일: PreToolUse 검증 훅, deny 규칙, plan 모드, 검증 게이트, 비가역성
  게이트, honesty gate. 프롬프트가 아니라 하네스가 강제.
- 장기 실행: durable step(멱등 키)·체크포인트·서킷 브레이커(반복 상한·무진전·
  동일오류·비용 예산).

### 5.9 하네스 실패 모드 (요약)

환각 수치·인용→도구 근거 강제·미근거 거부 / 사후 선택 편향→사전등록·전수기록
/ 사일런트 실패 전파→단계별 구조화 상태 / 무한 루프→하네스 강제 상한 /
미태그 데이터 혼합→DataPoint enum·honesty gate.

### 5.10 가설 생성·평가 (D1)

연구 루프(§5.3)의 가설 단계를 고도화한다. `hypothesis-gen` 서브에이전트가
문헌 갭(§14)·현 결과·연구 루프 상태에서 후보 가설을 생성하고, **Elo
토너먼트**(AI co-scientist식)로 순위화한다 — 쌍대 비교(신규성·검증가능성·
실현성·임팩트 기준) → Elo 점수. reflection 패스가 물리적 타당성을 검사
(`oracle`·`formulas` 대조, 알려진 물리와 모순 여부).

- UX: `maglab hypotheses "<주제>"` → 순위화된 가설 카드 — 각 카드에 아이디어,
  신규성 근거(문헌 인용), 검증 방법(§13.6 측정 계획 또는 시뮬 링크), 실현성·
  임팩트 점수, 추론 근거. 연구자가 선택 → 연구 루프·측정 계획에 투입.
- 무결성: 가설은 AI 제안임을 명시, 문헌에 그라운딩, 연구자가 결정. "AI가
  발견"이 아니라 "순위화된 후보 방향 + 근거".

### 5.11 이상 결과 설명 (D2)

결과가 기대·이론·문헌과 어긋날 때 물리적 설명 후보와 판별 방법을 제시한다
(가추 추론). 트리거: `consistency`(§11)가 불일치를 탐지하거나 연구자가
`maglab explain <데이터/결과>`.

- 과정: 후보 기전 생성(예: ρ_xy의 여분 hump → 토폴로지컬 홀 / 2차 자성상 /
  접촉 아티팩트 / 열 드리프트), 각 후보를 물리·문헌으로 그라운딩. 핵심 —
  각 후보마다 *판별* 측정/시뮬을 제안(무엇을 하면 후보들이 구별되는가).
- UX: `maglab explain` → 순위화된 설명 카드 — 각 카드에 기전, 왜 이 신호를
  낼 수 있는지, 지지·반박 증거, 판별 테스트. 연구자가 테스트를 선택.
- 무결성: 설명은 결론이 아닌 가설 — 신뢰도·증거 라벨 부착, 핵심은 판별
  테스트(결론 내지 말고 검증하라).

### 5.12 연구 루프 트리 탐색 알고리즘

§5.3은 연구 루프가 백트래킹 트리라고 했다. 그 트리를 구체 알고리즘으로 명시한다.

- **노드** = `{가설, 설계, 실행 상태, 결과, 분석 판단, 점수}`. 루트 = 연구 목표.
- **확장(best-first)** — 한 노드에서 오케스트레이터가 N개 자식(대안 가설·설계·
  파라미터)을 생성하고, 가장 유망한 노드부터 확장한다.
- **점수** — 각 노드를 §5.10 Elo + 결정론 검증(`oracle`·정적 검증) + (가능 시)
  `consistency` 일치도로 평가. 점수가 확장 우선순위를 정한다.
- **가지치기** — 막다른 가지(정적 검증 실패·물리 비타당·예산 초과)는 잘라내되
  *실패 유형*을 기록해 다른 가지가 같은 시도를 반복하지 않게 한다.
- **병렬** — cost-tier 0–1 노드는 서브에이전트로 병렬 확장, tier 2–3은 직렬·게이트.
- **분리** — `experiment-manager` 서브에이전트가 트리 상태·확장 결정을 소유
  (오케스트레이터의 전략 판단과 분리). 트리는 `checkpoint.py`로 영속 → 중단·재개.
- **종료** — 목표 달성 / 예산 소진 / 전 가지 막힘. 트리 전체가 provenance에 기록.

### 5.13 누적 연구 메모리

장기 메모리(§5.5)를 *런 간 누적*으로 확장한다. 한 Ralph 런·연구 루프가 끝나면
구조화 요약을 공유 풀에 적립한다.

- **적립 항목** — 확정 결과(`DataPoint`), 검증된 가설, **실패한 파라미터 영역**,
  예상 밖 이상, 효과적이었던 도구 설정.
- **저장** — `memories/research_pool/` 에 항목별 구조화 레코드(주제 태그·
  provenance 링크·타임스탬프). 벡터 색인 + grep 검색.
- **활용** — 새 런 시작 시 오케스트레이터가 풀을 질의해 관련 선행 결과·실패를
  컨텍스트에 JIT 주입 → 이미 시도해 실패한 영역을 재탐색하지 않는다.
- 프로젝트 간 공유 가능(연구자 동의 시). 수개월 떨어진 캠페인 사이에 지식이
  복리로 쌓인다.

### 5.14 스텝별 비용·자원 추적

`budget.py`를 확장한다. 모든 LLM 호출·도구 호출·시뮬 잡을 스텝으로 계량한다.

- 스텝마다 토큰·LLM 비용·wall-time·(시뮬이면) 코어-시간을 기록.
- 실시간 표시 — 상태 바와 `maglab cost`로 세션·런·Ralph 루프별 누적 비용 노출.
- 예산 게이트(§5.8)와 연동 — 비용 속도/누적이 상한에 접근하면 경고·에스컬레이션.
- provenance에 비용 메타데이터 부착 → "이 결과를 내는 데 얼마"가 사후 감사 가능.

### 5.15 무결성 가드레일 강화 — 차단 게이트 & 행동 검증

honesty gate(§17)를 *능동 차단*과 *행동 수준*으로 강화한다.

- **차단형 단계 게이트** — 저술(§16)·리뷰(§15) 파이프라인의 단계 경계에 차단
  게이트를 둔다. 통과 조건 미충족 시 다음 단계로 진행이 *불가*(경고가 아니라
  정지)다. 예: 저술 섹션 확정 전, 모든 인용이 §16.7 의미 검증을 통과하고 모든
  수치가 데이터 볼트에 존재해야 한다.
- **주장 단위 감사** — 생성 텍스트의 각 사실 주장을 추출 → 근거(`DataPoint` 또는
  인용 청크의 인용구·쪽·섹션 앵커)에 대조 → 미근거·과장 주장은 HIGH-WARN으로
  차단하고 연구자에게 표시.
- **행동 검증 훅(promise-check)** — 에이전트가 "X를 실행/기억했다"고 *말한* 것을
  실제 도구 호출 로그·provenance와 대조한다. 불일치(거짓 주장)면 플래그·정정 →
  환각을 데이터·인용을 넘어 *행동*까지 막는다.

### 5.16 서브에이전트 · 오케스트레이션 디자인

§5.3–5.4를 구현 수준으로 구체화한다 — 오케스트레이터와 서브에이전트 풀의
정의·계약·검증.

**서브에이전트 정의.** 서브에이전트 = `{시스템 프롬프트, 도구 집합, 모델,
격리 컨텍스트, 예산}`. MagLab은 각 서브에이전트를 `agents/<name>.md`(YAML
frontmatter + 본문=시스템 프롬프트)로 정의 — 스킬(§5.17)과 동일 파일 규약.
frontmatter 필드: `name` · `description`(오케스트레이터가 위임을 판단하는
트리거) · `tools`(허용 도구 — 최소권한 allowlist) · `model`(`opus`/`sonnet`/
`haiku`/`inherit`) · `max_turns`(내부 루프 상한) · `effort` · `context`(기본
격리; `fork`면 부모 컨텍스트 상속) · `skills`(선로드 스킬) · `mcp_servers`(이
에이전트에 스코프된 MCP) · `hooks`. 본문이 곧 시스템 프롬프트다. 서브에이전트는
부모 대화를 보지 않고 받은 과업 프롬프트만 보며, 압축된 결론만 반환한다(컨텍스트
격리가 존재 이유). 중첩 스폰 불가 — 2단 깊이까지.

**5대 오케스트레이션 위상.** §5.2 원칙("복잡성은 입증으로") — 단일 에이전트가
기본이고, 아래는 입증된 경우만 쓴다.

| 위상 | MagLab 적용 |
|---|---|
| 프롬프트 체이닝 | 고정 파이프라인 `gen→validate→run→parse→fit`·멀티스케일 핸드오프. 단계 사이 결정론 게이트 |
| 라우팅 | 질의 분류 → 핸들러·모델 라우팅(FAQ=haiku, 피팅=opus). §7.3 단계 라우팅 |
| 병렬화 | 문헌 N편 동시 분석(sectioning)·가설 앙상블(voting). 토큰 ~N배 |
| 오케스트레이터-워커 | 연구 루프(§5.12) — 서브과업이 사전 미정, 런타임 동적 분해 |
| 평가자-최적화자 | Loop A/C/D/E — 생성기 ↔ *다른* 평가기, 2–3회 상한 |

**서브에이전트 계약 (6요소)** — 부록 H의 4요소를 확장. 모든 서브에이전트
spec이 명시한다: ① 단일 목표(`description`이 위임 트리거) ② 입력 명세(받을
데이터·파일·형식) ③ **출력 스키마**(구조화 JSON — `status{success|partial|
failed}`·결과·`warnings`) ④ 도구 예산(`max_turns`·도구 allowlist) ⑤ 소스
가이드(읽을/읽지 말 곳) ⑥ 작업 경계·모호성 처리(미지 상황 시 추측 금지,
`failed` 반환).

**오케스트레이터 검증.** 서브에이전트 결과를 신뢰하기 전 4계층(§5.7 연계):
① 스키마 검사(결정론 — JSON 구조·필수 필드·타입·범위) ② 도메인 sanity
(`oracle` — 물리 범위·단위) ③ 신뢰도 신호(`status`·`warnings` → `partial`이면
재실행 또는 상향 모델) ④ LLM 평가자(앞 3계층이 부족할 때만, 저렴 모델).

**도구 큐레이션 · 모델 라우팅** — 역할별 최소권한:

| 역할 | 도구 | 모델 |
|---|---|---|
| 오케스트레이터 | 위임·읽기 | opus |
| 도메인 분석(피팅·시뮬) | 읽기·쓰기·실행 | sonnet |
| 탐색·문헌 정찰 | 읽기·검색 | haiku |
| 평가자·검증 | 읽기 | haiku |

**하네스 매니페스트.** 오케스트레이터의 라우팅 표를 `harness.manifest.json`에
선언한다: 등록된 서브에이전트·스킬·MCP 서버·명명 워크플로우(워크플로우 =
서브에이전트 실행 순서)·품질 게이트. 새 도메인 추가 = 매니페스트 한 항목.
문헌 도메인 구현은 §14.7.

**비용 · 실패 모드.** 멀티에이전트는 토큰 ~15× — 단일 에이전트로 되면 안 쓴다.
실패 모드(§5.9 확장): 조기 완료 선언→검증 단계 강제 / 캐스케이딩 오류→단계 간
스키마 게이트 / 도구 결과 통한 프롬프트 인젝션→결과 비신뢰·정화 / 무한 루프→
`max_turns`·예산 상한 / 신뢰경계 위반→서브에이전트 권한 ≤ 오케스트레이터.

### 5.17 스킬 시스템 심화 — SKILL.md 명세 · 저작 · 자동 생성

§5.6을 구현 수준으로 — SKILL.md 오픈 표준의 전체 명세, 저작 규칙, 스킬
*자동 생성*.

**SKILL.md 명세.** 스킬 = 디렉터리(이름=`name`). 구성: `SKILL.md`(필수) +
`scripts/`(실행 코드) + `references/`(도메인 문서·API) + `assets/`(템플릿) +
`evals/`(테스트). frontmatter:
- 이식 필드(전 에이전트 호환): `name`(1–64자 kebab) · `description`(트리거,
  ≤1024자) · `license` · `compatibility`(필요 패키지·환경) · `metadata`(자유
  키-값).
- MagLab 확장: `user-invocable`(false=Claude 전용 배경지식) · `disable-model-
  invocation`(true=사용자만 호출 — 안전임계용) · `paths`(자동활성 글롭) ·
  `allowed-tools`(사전승인) · `context: fork`(격리 서브에이전트로 실행).

**3단계 점진 공개** — 토큰 예산 명시(§5.6 재확인):
- **L1 메타데이터**(`name`+`description`) — 시작 시 항상 로드, ~100토큰/스킬.
  전체 스킬 색인 예산 = 컨텍스트 ~1%.
- **L2 SKILL.md 본문** — 트리거 시 로드, <5k토큰 권장(본문 ≤500줄). 세션 유지,
  compaction 후 재부착(스킬 공동 25k 예산).
- **L3 번들 파일** — 명시 접근/실행 시만. 스크립트 *코드*는 컨텍스트에 안 들고
  *출력*만 들어온다.

**저작 규칙.** `description`은 3인칭·"무엇을 한다 + 언제 쓴다"·도메인 어휘
(장비 모델명·물리량)로, 과소트리거를 막게 적극적으로. 본문은 명령형·≤500줄·
제약의 *이유*를 설명. 좁고 합성 가능하게(장비별 1스킬). 결정론·반복 작업은
`scripts/`로, 판단이 필요한 것은 인라인 지침으로.

**스킬 자동 생성** (§13.3 구체화) — `skill-creator` 패턴. 장비 매뉴얼(또는 임의
절차 문서) → 스킬:
1. **추출** — 매뉴얼 PDF 판독(§13.2) → 통신 인터페이스·파라미터 범위·초기화
   시퀀스·**안전 인터록**·측정 워크플로우·실패 모드.
2. **초안** — `SKILL.md`(frontmatter+퀵스타트) + `references/commands.md`(전체
   명령) + `references/safety.md`(인터록·한계) + `scripts/`(연결·측정·검증) +
   `evals/evals.json`(3–5 테스트 케이스).
3. **A/B 평가** — 서브에이전트 둘을 병렬로: 스킬 로드 vs 미로드(baseline).
   `evals.json` 과업 실행 → 채점 서브에이전트가 정량 단언으로 평가 → 벤치마크.
4. **반복** — 피드백을 일반화(테스트 과적합 회피) → 개선 → 재평가. `description`
   최적화 루프(트리거 쿼리 ~20개로 자동 튜닝).
5. **패키징** — `metadata`에 provenance(`source-document` SHA·생성기·장비
   시리얼). 안전임계 스킬은 `disable-model-invocation`.

**검증 · 결정표.** 구조 검증(frontmatter·명명·문자수·≤500줄·참조 1단계).
스킬 vs MCP vs 서브에이전트 vs 슬래시 커맨드:

| 수단 | 쓸 때 |
|---|---|
| 스킬 | 절차지식·워크플로우를 자동 적용 (장비 사용법, 효과 피팅 절차) |
| MCP 서버 | 외부 시스템 실시간 연결 (문헌 API·물질 DB·장비 상태) — §5.18 |
| 서브에이전트 | 격리 컨텍스트의 자율 과업 (대량 데이터 소화 후 압축 반환) — §5.16 |
| 슬래시 커맨드 | 번들 자원 없는 단발 지시 — 신규는 스킬 권장 |

### 5.18 MCP 통합 아키텍처 — 클라이언트 · 서버 · 레지스트리

§4·§7.1의 MCP 언급을 구현 수준으로. MagLab의 MCP 두 역할:
- **(A) 클라이언트** — 하네스가 호스트가 되어 외부 MCP 서버를 도구 소스로
  소비. 서버마다 세션 하나(문헌·물질 DB 등).
- **(B) 서버** — `maglab mcp`로 자체 MCP 서버 노출 → 외부 하네스(Claude
  Code 등)·협업자가 MagLab 도메인 도구 사용.

**3대 프리미티브** (MagLab 서버가 노출, 부록 B):
- **Tools** (모델 호출) — `fit_effect`·`sim_run`·`physics_compute` 등. 주석
  `readOnlyHint`·`destructiveHint`를 달아 승인 게이트(§5.8)가 활용.
- **Resources** (앱 제어 데이터) — `maglab://material/{id}`·`maglab://
  experiment/{id}/summary`·`maglab://effects` 등 URI. 참조 데이터를 도구 호출
  없이 컨텍스트에 주입.
- **Prompts** (사용자 워크플로우) — `analyze_experiment`·`draft_methods` 등
  슬래시 워크플로우.

**전송.** stdio(로컬 서브프로세스 — 기본, 샌드박싱 쉬움) / Streamable HTTP
(원격·다중 클라이언트·협업자 공유). 로컬 MCP는 stdio, 공유 시 HTTP.

**고급 기능.** progress(장기 시뮬 진행률) · elicitation(서버가 측정 파라미터를
폼으로 요청 — §13.6 연동) · cancellation(Ctrl+C → `notifications/cancelled`) ·
logging · completions(`maglab://` URI 자동완성). sampling(서버→호스트 LLM 호출)은
표준에서 비권장 방향 — 미사용, 도구 반환 패턴으로 대체.

**MCP 서버 레지스트리** (`.maglab/mcp.json`). 서버마다: `type`(stdio/http) ·
`command`/`args`/`env` 또는 `url`/`headers`/`oauth` + MagLab 확장 `trust_level`
(trusted/restricted/untrusted) · `enabled` · `always_load`. **lazy 연결**(과업에
필요한 서버만 기동) · **도구 네임스페이싱**(`arxiv::search_papers` — 충돌 방지) ·
환경변수 확장.

**도구 과다 대응.** 서버 5+개·도구 50+개면 스키마만 55–100k 토큰. **동적 도구
로딩**: 도구 *이름·색인*만 선로드, 스키마는 LLM 요청 시 — §5.6 스킬 3단계 공개와
동형. `always_load`는 소수 상시도구만.

**보안.** 위협: 도구 설명·결과를 통한 프롬프트 인젝션, 악성 서버, confused-
deputy, 토큰 패스스루(금지). 완화: 신뢰 서버 allowlist · `trust_level`별 승인
게이트(§5.8 — `destructiveHint`·`openWorldHint` 도구는 사람 승인) · stdio
서브프로세스 샌드박싱 · 원격은 OAuth 2.1 · 버전 핀 · 도구 결과 비신뢰 취급.
도구 주석은 *힌트*지 보증이 아니다.

**번들 커넥터.** 검증된 논문검색 MCP 3종을 기본 추천 커넥터로 등록한다 —
라이선스·역할은 §14.7.

## 6. Ralph 루프 — 자율 반복 세션 엔진

### 6.1 기법

Geoffrey Huntley의 Ralph 기법 — 에이전트를 `while` 루프로 반복 호출하며
**매 iteration 신선한 컨텍스트**를 주고 *상태는 디스크 파일*에 둔다. 컨텍스트
고갈·compaction 드리프트를 원천 차단.

### 6.2 두 실행 모드 + 서킷 브레이커

| 모드 | 메커니즘 |
|---|---|
| 인-세션 | 하네스의 `Stop`-등가 훅이 종료를 가로채 원 프롬프트 재주입. 상태 `.maglab/ralph.local.md`(`active`·`iteration`·`max_iterations`·`completion_promise`) |
| 분리형 신선-컨텍스트 | 외부 루프가 `maglab` 에이전트를 매번 새로 호출, 상태는 파일+git |

`core/ralph.py`. 완료 신호 `<promise>DONE</promise>`(진짜 참일 때만). 기본
`max_iterations=20`, 오버나잇 상한 50. iteration마다 git 커밋. 서킷 브레이커:
3회 무진전·동일오류 5회·출력 유사도 >0.95·비용 속도 초과 → 중단·에스컬레이션.
빌드 iteration은 저렴한 모델, 계획 패스만 고성능 모델.

### 6.3 MagLab의 Ralph 루프

| 루프 | 패턴 | 절 |
|---|---|---|
| A 원고 리뷰→패치→재리뷰 | Evaluator-Optimizer(문서 스케일), 분리 reviewer/reviser | §15.5 |
| B 실험코드 구현→테스트→수정 | 에이전틱 TDD, 목 계측기 `pytest -x` | §13.4 |
| C 논문 초안→비평→수정 | Self-Refine, 도메인 인식 critic, PDF readback | §16.5 |
| D 효과 피팅 개선 | 피팅→잔차·물리경계 검사→모델/초기값 조정→재피팅 | §11.4 |
| E figure 정제 | 렌더→비전 모델 critic→수정 (MatPlotAgent식 시각 피드백) | §12.5 |

휴먼게이트: 루프 시작은 Tier 2(승인), 마일스톤마다 일시정지·통지, 원고/코드
적용은 Tier 3(사람).
